

## Fix 4 Issues: Destination Photos, PDF, Copy Link, Scroll

### Investigation Results

1. **Wikipedia API works** — tested `Shimla` and got valid thumbnail + full image URLs. The code logic with `extractPlaceName` and fallback retry is correct.
2. **Share-trip edge function works** — tested and got `shareCode: "rkccKrLy"` successfully.
3. **PDF export** — code structure is solid but uses ASCII-only font which strips non-Latin characters.

### Root Causes & Fixes

---

### 1. Destination Photos Not Loading

**Root cause**: Wikipedia API thumbnail URLs from `upload.wikimedia.org` may be blocked by browser referrer policies or fail silently. The code has no error logging, making debugging impossible. Additionally, the `img` `onError` handler catches broken images but CORS-blocked fetches silently fail in the `fetch()` call.

**Fix in `src/components/DestinationPhotos.tsx`**:
- Add `referrerPolicy="no-referrer"` to all `<img>` tags (Wikipedia sometimes blocks based on referrer)
- Add `crossOrigin="anonymous"` attribute
- Add console logging in the fetch to debug failures
- Use a CORS proxy fallback: if the direct Wikipedia API fetch fails, try with `no-cors` mode or use the Wikipedia `action=query` API as alternative

---

### 2. PDF Export Issues

**Root cause**: jsPDF's default Helvetica font cannot render Hindi/Unicode characters or special symbols. The `safe()` function strips ALL non-ASCII characters, which removes valid content.

**Fix in `src/components/ExportPDF.tsx`**:
- Keep the ASCII-safe approach but improve the conversion — instead of stripping non-ASCII silently, transliterate common Hindi characters or at minimum preserve the readable text
- Add proper page margins and headers/footers with page numbers
- Add a "Generated by TripMap Planner" footer

---

### 3. Copy Link Not Working

**Root cause**: The share-trip backend function works correctly (verified). The issue is `navigator.clipboard.writeText()` fails in the Lovable preview iframe due to permissions policy. The fallback catches the error and copies plain text instead, but users see "Itinerary text copied (link creation failed)" — misleading since the link was created but clipboard failed.

**Fix in `src/components/ShareButtons.tsx`**:
- Separate the two error cases: link creation failure vs clipboard failure
- Use `document.execCommand('copy')` as a second fallback for clipboard
- Show the generated URL in a small input field that users can manually copy if clipboard API fails
- Add a toast with the actual URL so users can see it

---

### 4. Scroll Issues on Itinerary Page

**Root cause**: The itinerary content area uses `min-h-[calc(100vh-60px)]` with `flex flex-col`, but the map section has a fixed `h-[40vh]` which combined with the flex layout can prevent natural document scrolling in some viewports.

**Fix in `src/pages/Itinerary.tsx`**:
- Remove the `flex flex-col min-h-[calc(100vh-60px)]` wrapper and use natural block flow
- Remove `flex-1` from content area — let it flow naturally
- Ensure the page scrolls as a normal document
